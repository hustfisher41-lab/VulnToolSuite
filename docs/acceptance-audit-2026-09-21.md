## 1. 总体评价

当前系统已具备一条可实际运行的“CVE/NVD 采集 → 统一结构解析 → 多源融合 → SQLite 可追溯存储 → 本地向量生成 → 关键词/向量混合检索 → SFT/RAG 等训练数据导出”链路。主库包含 100,000 个统一漏洞实体，原始来源记录 110,000 条，数据和训练集规模不是空壳。

当前系统还不具备需求中定义的完整生产闭环。主要缺口是：AVD/CNNVD 在线采集受站点验证机制阻断；持久化层不是 PostgreSQL；向量后端不是 Qdrant；默认编码器是确定性特征哈希而非语义模型；Structured Security Test Trajectory 已有基础表和 fixture 数据但没有真实授权环境轨迹；没有已连接的 Docker/独立 VM 执行后端、真实靶场任务和内核运行时行为采集。旧项目中的 React/Qdrant 代码与本项目主库和 API 不兼容，不能计入当前交付能力。

本次修复没有伪造数据，也没有把未连接的后端显示成成功。新增 Web 验收台直接读取真实数据库，并明确显示索引、数据集和沙箱状态。

## 4. 功能缺口清单

### P0

1. 主库没有与当前编码器兼容的向量，`search` 直接失败。处理：全量重建主库索引并真实检索验证。
2. Web 验收入口缺失，无法演示数据库、索引、数据集与检索状态。处理：新增只读真实数据看板和汇总接口。
3. `/records` 与单条详情会先加载全部 100,000 条记录，存在明显内存和延迟风险。处理：改为 SQL 分页和定点查询。

### P1

1. AVD/CNNVD 没有可用采集通道。
2. PostgreSQL 与 Qdrant 未实现；当前替代实现为 SQLite 结构化表和 SQLite 小库精确/大库两阶段向量检索。
3. 默认编码器不是语义模型，缺少固定模型版本和语义检索评测。
4. Patch/Issue 关联与可信 enrichment 缺失。
5. Structured Security Test Trajectory 基础模型、导入导出已补齐，但真实授权环境轨迹仍缺失。
6. 执行后端未配置；Docker daemon、靶场、容器限制验证和真实运行监控均未打通。
7. 现有两个历史 `running` job 没有在进程中断后自动归档，任务状态需要恢复机制。
8. Preference 数据集只有候选，没有人审后的正式样本。

### P2

1. 增加产品分布、重复率和 embedding failure 的预计算指标，避免大库实时扫描。
2. 增加检索 Recall@K、MRR、分过滤条件延迟等基准。
3. 增加 PoC 审核工作流和数据版本审批记录。
4. 有真实训练后再接入 MLflow；当前不生成模拟训练曲线。

### 7.3 本地简化闭环

执行 `simple-closure` 后，`output/simple-closure/closure-report.json` 的 8 项检查全部通过：主库存在、索引完整、检索返回、目标漏洞命中、知识训练集存在、轨迹入库、轨迹训练集存在、fixture canary 通过。CVE-1999-0001 排名第 1；复用知识数据 94,400 条；轨迹库现有 2 条、每条 3 个可观察步骤和 2 个运行事件。

该结果代表“本地知识与 fixture 轨迹闭环可用”，不代表真实沙箱闭环。Docker Desktop 实测因本机 `dockerInference` 运行套接字路径异常而启动崩溃；未执行恢复出厂、删除数据或其他破坏性修复。真实容器/VM 执行、隔离和内核事件监控仍保持失败关闭。

## 8. 最终结论

当前系统**尚未**具备“采集—处理—PostgreSQL—Qdrant—训练数据—安全测试—隔离执行—运行监控—可视化”的完整闭环。

当前可交付、可演示的范围是：**CVE/NVD 采集、统一解析、SQLite 可追溯存储、多源融合、确定性向量生成、本地混合检索、训练数据构建和真实数据 Web 看板**。这部分有真实数据、真实调用和自动化测试支撑。

安全测试后半链路必须等执行环境和真实授权轨迹就绪后继续建设。以“只要能用”为交付口径，当前 P0 修复完成后可作为漏洞知识检索与数据集构建版本交付；不能作为完整安全测试沙箱平台验收通过。
